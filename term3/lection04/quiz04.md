# Контрольный тест (quiz) №4

Охват: материалы [лекции 4](lection04.md) и [семинара 4](../seminar04/seminar04.md) (обновление информационной базы в БСП)

Формат: вопросы с выбором одного верного варианта.

---

### Вопросы

1. Почему одного применения обновления конфигурации недостаточно, если логика перенесла реквизит из шапки документа в табличную часть?

- А) Обновление КД меняет метаданные; сами по себе значения в старых документах в новую структуру не «переезжают» — нужна прикладная миграция в обработчиках.
- Б) В типовой поставке табличные части у документов запрещены: платформа не даст сохранить такую конфигурацию.
- В) Регистр «Версии подсистем» при каждом обновлении полностью очищается, поэтому перенос не отслеживается.
- Г) Обработчики обновления выполняются только в файловой базе и в клиент-сервере к ним нет доступа.

2. Как подсистема БСП определяет, какие обработчики нужно выполнить при переходе с одной версии на другую?

- А) Случайно выбирает подмножество модулей из списка общих модулей конфигурации при каждом запуске.
- Б) Сопоставляет версию в данных (регистр «Версии подсистем») с целевой версией в конфигурации и строит цепочку промежуточных шагов.
- В) Смотрит только на последний символ номера релиза и по нему однозначно выбирает один обработчик.
- Г) Список обработчиков не зависит от версий: выполняются все объявленные процедуры при любом обновлении.

3. Когда в регистре «Версии подсистем» выставляется признак основной конфигурации?

- А) Для любой подсистемы, имя которой начинается с префикса «Демо», независимо от имени конфигурации.
- Б) Только если информационная база развёрнута на кластере из не менее чем двух рабочих серверов 1С.
- В) Когда имя подсистемы совпадает с именем конфигурации — так помечается «основная» подсистема.
- Г) Признак не используется в БСП и оставлен только для совместимости со старыми релизами платформы.

4. Что нужно сделать, чтобы подключить собственный общий модуль обновления к БСП (по лекции)?

- А) Удалить из конфигурации типовой модуль `ОбновлениеИнформационнойБазыБСП`, иначе будет конфликт имён.
- Б) Достаточно изменить строку версии в свойствах корневого узла конфигурации — регистрация модуля не нужна.
- В) Собственный модуль обновления допускается только в расширении; в основной конфигурации его подключить нельзя.
- Г) Взять шаблон модуля, скопировать, зарегистрировать подсистему в `ПриДобавленииПодсистем`, указать БСП в требуемых, при необходимости снять с поддержки объекты для правок.

5. Чем по назначению отличаются процедуры `ПриДобавленииПодсистем` и `ПриДобавленииОбработчиковОбновления`?

- А) Первая описывает подсистему и подключает модуль обновления; вторая формирует таблицу обработчиков и их версий.
- Б) Это синонимы: компилятор подставляет одну процедуру вместо другой без различий по смыслу.
- В) Первая вызывается только в тонком клиенте при открытии формы; вторая — только на сервере при записи.
- Г) Вторая процедура в типовой БСП не используется: обработчики задаются только через свойства метаданных.

6. В колонке «Версия» строки таблицы обработчиков обновления задаётся версия, до которой относится переход с данным обработчиком — это означает:

- А) Обработчик сработает при любом составе конфигурации, проверка версии в таблице не выполняется.
- Б) Обработчик входит в цепочку доведения данных до состояния, согласованного с целевой версией (детали — в документации БСП).
- В) Версию можно не указывать, если в комментарии к строке есть пометка «Отладка обработчика».
- Г) Колонку заполняют только для объектов в расширении; в основной конфигурации она игнорируется.

7. Почему процедура-обработчик, вызываемая подсистемой обновления из другого общего модуля, должна быть `Экспорт`?

- А) Без ключевого слова `Экспорт` модуль с обработчиком вообще не сохраняется в дереве метаданных.
- Б) Для обработчиков обновления ключ `Экспорт` запрещён стандартом разработки на платформе 1С.
- В) Иначе процедура недоступна для вызова «снаружи» модуля — подсистема не сможет обратиться к ней по имени.
- Г) Достаточно директивы `&НаСервере` в модуле формы — отдельный экспорт процедуры не требуется.

8. Зачем при программной записи объекта из обработчика обновления выставляют `ОбменДанными.Загрузка = Истина` и отключают автозаполнение получателей обмена?

- А) Чтобы ускорить проведение документа и сократить время блокировок при параллельной работе пользователей.
- Б) Это обязательное требование только для формы, открытой в веб-клиенте; в толстом клиенте не нужно.
- В) Чтобы платформа принудительно сняла проведение и очистила движения по всем регистрам документа.
- Г) Чтобы при технической миграции не запускать лишние сценарии обмена и автоматическую регистрацию на планах.

9. Зачем в типовом сценарии БСП вызывать `ОбновлениеИнформационнойБазы.ЗаписатьОбъект` вместо «голой» записи объекта?

- А) Метод задаёт типовые параметры записи для обновления ИБ (в т.ч. обмен и загрузка) в одном вызове.
- Б) Метод после записи помечает документ к удалению и очищает движения для упрощения отладки.
- В) Метод доступен только в тонком клиенте; на сервере нужно вызывать обычный `Записать()`.
- Г) Без этого вызова конфигуратор не откроет дерево метаданных до перезапуска информационной базы.

10. Как повторно прогнать цепочку обработчиков в учебной базе без выпуска нового релиза (по лекции)?

- А) Полностью удалить регистр сведений «Версии подсистем» из конфигурации и загрузить базу заново.
- Б) Понизить версию своей подсистемы в регистре (включив редактирование) и снова запустить обновление ИБ.
- В) Достаточно перезагрузить компьютер разработчика — цепочка выполнится автоматически при входе в базу.
- Г) Повторный запуск обработчиков запрещён: без новой сборки конфигурации сценарий недоступен.

11. Чем монопольный режим выполнения обработчика принципиально отличается от отложенного (вводно по курсу)?

- А) Монопольный режим доступен только при работе через веб-клиент; в толстом клиенте он недоступен.
- Б) Отложенный режим в БСП не предусмотрен: все обработчики выполняются только монопольно.
- В) Монопольный — до работы пользователей там, где иначе ошибки на «сырых» данных; отложенный — после старта, часто в фоне.
- Г) Отличий нет: это два названия одного режима в разных версиях платформы.

12. Почему обработчик обновления должен быть идемпотентным (семинар)?

- А) Чтобы код корректно выполнялся только при СУБД PostgreSQL; в других СУБД это не требуется.
- Б) Стандарты 1С запрещают идемпотентность: каждый прогон должен менять данные, иначе ошибка компиляции.
- В) Под идемпотентностью в методичке имеется в виду только использование индексов в запросах.
- Г) Чтобы повторный запуск после сбоя или доработки не удваивал эффект и не портилась уже исправленная часть данных.

13. Можно ли в обработчике Б полагаться, что обработчик А уже обязательно выполнился раньше?

- А) Нет: порядок вызова разных обработчиков не детерминирован — зависимую логику нужно объединять в одном.
- Б) Да: платформа гарантирует алфавитный порядок имён процедур при любом обновлении.
- В) Да: если у обоих указана одна и та же версия подсистемы, порядок всегда строго фиксирован.
- Г) Да, но только если оба обработчика размещены в модуле менеджера одного и того же объекта.

14. Какое свойство подсистемы должно быть выставлено для допустимости многопоточного отложенного обработчика (семинар)?

- А) Флаг «Использовать только в файловой базе» — иначе многопоточность не активируется.
- Б) Режим выполнения отложенных обработчиков — параллельно (не последовательно).
- В) Опция «Отключить фоновые задания» для подсистемы, чтобы не было гонок потоков.
- Г) Свойство подсистемы на многопоточность не влияет: всё определяется только константой числа потоков.

15. Что регистрирует вызов `ОбновлениеИнформационнойБазы.ОтметитьКОбработке` и какая типичная ошибка при вызове (семинар)?

- А) Регистрирует пользователя в справочнике; при неправильном вызове чаще всего возникает ошибка прав доступа.
- Б) Выполняет проведение документов пакетом; типичная ошибка — «документ не проведён» из-за даты запрета.
- В) Ставит объекты в очередь на плане «Обновление информационной базы»; часто путают порядок параметров — «недостаточно параметров».
- Г) Метод устарел и отсутствует в актуальных версиях БСП; вызов всегда приводит к «процедура не найдена».

16. Что возвращает `ДанныеДляОбновленияИнформационнойБазыВМногопоточномОбработчике` и как обходят строки (семинар)?

- А) Одну ссылку на документ; цикл по таблице не нужен — достаточно одного обращения к значению.
- Б) Всегда пустое значение: строки заполняются только при вызове из клиентского приложения.
- В) Только номер текущего сеанса и идентификатор фонового задания без списка объектов.
- Г) Таблицу значений порции; в цикле обходят строки таблицы, а не «голые» ссылки без строки.

17. Зачем при `ПолучитьОбъект()` = `Неопределено` (битая ссылка) вызывать `ОтметитьВыполнениеОбработки` и продолжать цикл (семинар)?

- А) Чтобы снять ссылку с очереди и не зациклиться на «мёртвом» объекте при повторных проходах.
- Б) Чтобы полностью удалить план обмена «Обновление информационной базы» из конфигурации.
- В) Чтобы открыть пользователю форму документа с предупреждением о необходимости ручного ввода.
- Г) Так делать нельзя по стандарту: при `Неопределено` нужно прервать всё обновление исключением.

18. Почему в многопоточном отложенном обработчике нельзя «ронять» весь конвейер бездумным `ВызватьИсключение` для одной строки (семинар)?

- А) В языке 1С исключения полностью запрещены: компилятор не пропустит оператор `ВызватьИсключение`.
- Б) Ошибку по одному объекту разумнее записать в журнал регистрации, не останавливая обработку остальных без нужды.
- В) Исключение в фоне всегда игнорируется платформой, поэтому оно не влияет на другие потоки.
- Г) В многопоточном режиме журнал регистрации отключён: исключение просто теряется.

19. Почему при отладке из конфигуратора многопоточный отложенный обработчик может вести себя как однопоточный (семинар)?

- А) Отладчик платформы не подключается к серверным процессам — точки останова в обработчике не срабатывают.
- Б) Конфигуратор не поддерживает точки останова в серверных модулях — отладка там невозможна.
- В) При отладке из конфигуратора фактически выполняется однопоточный режим, даже если указана многопоточность.
- Г) Однопоточность при отладке свойственна только файловой базе; в клиент-сервере потоки не сужаются.

20. Какой ориентир по числу потоков фонового обновления относительно сервера и размеру порции упоминался на семинаре?

- А) Потоков должно быть больше числа ядер; порция — не менее 100 000 объектов для устойчивости.
- Б) Число потоков фиксировано платформой и не настраивается ни константой, ни параметрами БСП.
- В) Порция всегда ровно один документ независимо от объёма базы и настроек производительности.
- Г) Потоков не больше числа ядер; порция порядка ~1000, очень большие порции — риск долгого фонового задания.
