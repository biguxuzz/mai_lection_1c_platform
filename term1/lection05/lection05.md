### Блок 1: Примитивные типы данных

#### 1.1 Булевый тип

**Булевый тип** — логические значения.

**Представление:**

- В коде: `Истина`, `Ложь` (или `True`, `False`)
- Для пользователя по умолчанию часто **«Да» / «Нет»**; представление можно настроить

**Логические операции:** `И`, `ИЛИ`, `НЕ`

```1c
Переменная1 = Истина;
Переменная2 = Ложь;
Результат = Переменная1 И Переменная2; // Ложь
```

#### 1.2 Числовой тип

**Особенности (как на лекции):**

- В **коде** дробная часть задаётся **точкой**; ввод с **запятой** в полях ввода и код — разные контексты; несоответствие может дать **ошибку**
- **Остаток от деления** (`%`) часто используется в циклах и перечислениях

**Арифметика:** `+`, `-`, `*`, `/`, `%`

```1c
Число1 = 10.5;
Число2 = 3;
Результат = Число1 + Число2;
Остаток = Число1 % Число2;
```

#### 1.3 Строковый тип

**Особенности:**

- Строковые литералы в **двойных кавычках**
- В **одинарных кавычках** в 1С задаётся прежде всего **дата**; одинарные кавычки **не** используются как основной способ задать произвольную строку (в отличие от некоторых других языков)
- Внутри двойных кавычек доступны служебные последовательности (например, перевод строки для многоязычных представлений)

**Неявные преобразования при конкатенации (как разбирали на лекции):**

- Выражение вида **строка + число** обычно приводит число к строке — ошибки нет
- **Число + строка:** платформа пытается привести строку к числу; если **не удаётся** — **исключение**
- Если строка числу соответствует (в т.ч. с разделителем, как в локали), преобразование может пройти успешно

#### 1.4 Тип «Дата»

**Особенности:**

- Литерал даты в **одинарных кавычках**
- **Разделители** в записи даты можно подставлять разные — платформа их **убирает** и разбирает компоненты (год, месяц, день, при необходимости время)
- **Арифметика:** прибавление **числа** к дате интерпретируется в **секундах** (например, `+ 60` — минута, `+ 86400` — сутки, как `24*60*60`)
- Неполная или некорректная комбинация **с разделителями** может дать **исключение**; обсуждались «трюки» платформы с записью **без пробелов** — ориентир: нужны как минимум **год, месяц и день**

```1c
Дата1 = '2024.01.12';
Дата2 = Дата1 + 60;              // +60 секунд
Дата3 = Дата1 + 60 * 60 * 24;    // +1 день
```

#### 1.5 Составные типы

**Составной тип** — в одном реквизите допускаются значения разных типов.

**Примеры из практики:** измерения регистров, **регистратор** (приход/расход и т.д.).

**Рекомендация:** по возможности **избегать** составных типов — они усложняют код и сопровождение.

### Блок 2: Коллекции значений

#### 2.1 Массив

**Массив** — не типизированный: в один массив можно добавлять значения **разных типов**.

**Методы и обход:** `Добавить`, `Удалить(Индекс)`, поиск, **верхняя граница**, цикл `Для Каждого ... Из ...`

**Индексация:** с **нуля**; доступ `Массив[Индекс]`

**Циклические ссылки:** массив может содержать **ссылку на себя** (в т.ч. вложенный массив с обратной ссылкой) — технически обращение по индексу возможно, но для **сборщика мусора** счётчик ссылок на цикл **не обнуляется**, и структура может **оставаться в памяти** до конца сеанса. Для больших данных это риск; иногда такую схему используют осознанно.

**Про `Сообщить()`:** для учебных примеров удобно; в реальных сценариях (фоновые задания, сервер) сообщение пользователю может быть не видно — предпочтительны **средства вывода сообщений пользователю** с привязкой к форме/строке.

```1c
Массив = Новый Массив;
Массив.Добавить("Элемент1");
Массив.Добавить(123);

Для Каждого Элемент Из Массив Цикл
    Сообщить(Элемент);
КонецЦикла;
```

#### 2.2 Структура

**Структура** — коллекция **ключ → значение** (например, поля «студент», «группа», **год поступления**).

**Обход:** в цикле `Для Каждого` доступны **ключ** и **значение**

**Мутабельность и передача:** структура и массив — **изменяемые** типы; при отсутствии «тяжёлых» объектных ссылок их удобно передавать **между клиентом и сервером**

**Циклические ссылки** — та же проблема утечки, что и у массивов; **избегать**

```1c
Студент = Новый Структура;
Студент.Вставить("ФИО", "Иванов Иван Иванович");
Студент.Вставить("Группа", "ИТ-21");
Студент.Вставить("ГодПоступления", 2024);

Для Каждого Элемент Из Студент Цикл
    Сообщить(Элемент.Ключ + ": " + Элемент.Значение);
КонецЦикла;
```

#### 2.3 Список значений и модальность / асинхронность

**Список значений** — элементы с **значением** и **представлением**; чаще связан с **формами** и выбором пользователя. От **соответствия** отличается наличием **представления** у элементов (как акцентировалось на лекции).

**Синхронный выбор** `ВыбратьЭлемент()` в типовых настройках **тонкого клиента** может приводить к сообщению о **запрете модальных окон** — нужен **асинхронный** выбор.

**Асинхронный сценарий (идея):**

- `Обещание = Список.ВыбратьЭлементАсинхронно();`
- получение результата через **`Ожидать`** (контекст **асинхронной** клиентской процедуры / выполнения алгоритма асинхронно — как настраивалось в демонстрации)

**Модальность в конфигурации:** режим **«не использовать модальность»** блокирует ожидание пользователя в коде; смена на допуск предупреждений может разрешить **модальный** `ВыбратьЭлемент`, но **блокирует весь клиент** на время диалога и **неприменима для веб-клиента** (там модальные вызовы недоступны)

**Про `Выполнить`:** выполнение произвольного кода из строки **небезопасно** (риск инъекций); на промышленных стендах часто **запрещают**; плюс сочетание с асинхронностью неудобно

**Исторический контекст:** до появления компактного синтаксиса `Асинх` / `Ожидать` (развитие с определённых версий платформы, на лекции упоминалась ветка **8.3.27+**) типовой обход — **обработчики ожидания** и клиентские экспортные процедуры; в **БСП** новый стиль встречается не везде

```1c
ВидТовара = Новый СписокЗначений;
ВидТовара.Добавить(1, "Услуга");
ВидТовара.Добавить(2, "Работа");

// Асинхронный выбор (концептуально; требуется асинхронный контекст процедуры)
Обещание = ВидТовара.ВыбратьЭлементАсинхронно();
Результат = Ожидать Обещание;
```

**Замечание с лекции:** поведение кода на **файловой** и **серверной** базе может различаться; ориентир для разработки под прод — **серверная** ИБ, чтобы не получить сюрпризы после переноса

#### 2.4 Таблица значений

**Таблица значений** — строки и колонки, по смыслу близко к таблице БД.

**Как на лекции:**

- Таблица значений рассматривалась как тип, который **нельзя передавать между клиентом и сервером** (в отличие от мутабельных структуры/массива без «тяжёлых» ссылок); на **клиенте** для таких операций тип **не подходит**
- Колонки **желательно типизировать** (`ОписаниеТипов`)
- Обход строк, поиск (`НайтиСтроки` со **структурой отбора**), добавление строк

**Демонстрация:** выполнение примеров в **консоли кода** на **сервере** (открытие **внешней обработки** «консоль кода» из файла)

```1c
Студенты = Новый ТаблицаЗначений;
Студенты.Колонки.Добавить("Фамилия", Новый ОписаниеТипов("Строка"));
Студенты.Колонки.Добавить("Имя", Новый ОписаниеТипов("Строка"));
Студенты.Колонки.Добавить("Группа", Новый ОписаниеТипов("Строка"));
Студенты.Колонки.Добавить("ДатаЗачисления", Новый ОписаниеТипов("Дата"));

НоваяСтрока = Студенты.Добавить();
НоваяСтрока.Фамилия = "Иванов";
НоваяСтрока.Имя = "Иван";
НоваяСтрока.Группа = "ИТ-21";
НоваяСтрока.ДатаЗачисления = ТекущаяДатаСеанса();

СтруктураПоиска = Новый Структура("Фамилия, Имя", "Иванов", "Иван");
НайденныеСтроки = Студенты.НайтиСтроки(СтруктураПоиска);
```

**Индексы** по колонкам таблицы значений (как в плане курса) ускоряют поиск на больших объёмах, но имеют стоимость при изменении данных — актуально для тяжёлых обработок

## Резюме по фактическому содержанию записи

1. **Файлы:** `.dt` — загрузка ИБ; `.epf` — внешние обработки; конфигурация выдаётся отдельным файлом по смыслу занятия  
2. **Развёртывание:** новая ИБ, файловая или серверная (WSL), нюансы **лицензии** и сети  
3. **Типы:** булево, число (точка в коде, `%`), строки и кавычки, дата и секунды, составные типы — по возможности избегать  
4. **Коллекции:** массив (в т.ч. циклические ссылки и память), структура, список значений (модальность / `Асинх` / `Ожидать`), таблица значений — в основном **сервер** и консоль кода  
5. **Практика:** контекст клиент/сервер критичен; разработка только на файловой базе может скрыть ошибки серверного поведения
