# Семинар 6: Подключаемые команды и собственные команды (БСП)

**Продолжительность:** ~90–120 минут (по объёму двух фрагментов записи)  
**Целевая аудитория:** Студенты 3 курса, курс по библиотеке стандартных подсистем  
**Курс:** Библиотека стандартных подсистем  

**Источники занятия:**

- `БСП_12_Подключаемые_команды.txt` — подключение подсистемы к формам списка и документа **«Приобретение товаров и услуг»**, отчёт по движениям.  
- `БСП_13_Собственные_команды.txt` — команды **«Создать на основании»** (приобретение → реализация), условия видимости, произвольная команда на форме списка **«Демо счёт на оплату покупателям»**.

## Цель семинара

Освоить подсистему **«Подключаемые команды»**: роль в интерфейсе (подменю **Отчёты**, **Создать на основании**, **Заполнение** и др.), требования к форме (**ссылка** в списке с **«Использовать всегда»**), структура модуля формы по **стандарту 400** (п. 1.6), вставки из инструкции БСП (**ПриСозданииНаСервере**, служебные процедуры, **при активизации строки** для списка), смысл префикса **`Подключаемый`**, перенос выполнения на сервер, обработчик ожидания и **обновление команд**. Подключить **отчёт по движениям** через движения документа. Реализовать **создание на основании** (менеджеры документов, регистрация объекта в **ПриОпределенииОбъектовСКомандамиСозданияНаОсновании**), условия видимости (**ДобавитьУсловиеВидимостиКоманды**) и обновление видимости при смене реквизитов. Добавить **свою команду** через **ПриОпределенииКомандПодключенныхКОбъекту**, обработчик и дополнительные параметры; зафиксировать **риски** использования служебных свойств и обхода программного интерфейса БСП.

## Необходимые предзнания

- Лекции/семинары по БСП, общие модули, формы документов и списков  
- Документация БСП на ИТС по подсистеме «Подключаемые команды»

## План семинара

### Блок 1. Подсистема «Подключаемые команды» в интерфейсе

- Подсистема нужна многим другим подсистемам БСП: **печать**, **отчёт о движениях документа**, **рассылка отчётов** и т.д.
- Позволяет выводить **команды** на **формы списков** и **объектов**; команды можно **группировать** в подменю.
- В типовом наборе сразу участвуют три подменю: **Отчёты**, **Создать на основании**, **Заполнение объектов** (последнее не видно, если к объекту не подключено ни одной команды такого вида).
- Отдельные подсистемы (например **печать**) могут добавлять **свои** подменю.
- Доступна **настройка видимости**: например, команда только для определённой хозоперации или при сумме документа **больше** заданной; при **множественном** выборе в списке команда доступна, только если она доступна **для всех** выделенных объектов.

---

### Блок 2. Подготовка модулей форм (стандарт 400)

- По **стандарту разработки № 400** (п. 1.6) взять **структуру модуля формы** и вставить в модуль **формы списка** и **формы документа** (при необходимости без блока описания переменных).
- Для списка: единственная таблица — в область **«Список»**; **«Только мои документы»** и **ПриСозданииНаСервере** — в нужные области (в т.ч. служебные процедуры).
- Для документа: переименовать таблицу формы, например, в **«Товары»**; обработчики **начала/окончания заполнения ТЧ**, **заполнить из временного хранилища** — перенести в служебные процедуры.

---

### Блок 3. Форма списка: ссылка и подключение по инструкции

- Для документа **«Приобретение товаров и услуг»** создать **форму списка**; для подключаемых команд на форме списка обязательно вывести **колонку со ссылкой**.
- Реквизит **«Склад»** (по смыслу демо) можно добавить; ссылку разумно сделать **последней** колонкой, скрыть через **пользовательскую видимость**, но для реквизита списка **«Ссылка»** установить флаг **«Использовать всегда»** — иначе подсистема **не сможет** корректно работать (это отражено в **инструкции** БСП).

Далее по **инструкции** подключения к форме:

1. В **ПриСозданииНаСервере** — вставить код из инструкции (вызов программного интерфейса подсистемы).
2. В **служебные процедуры и функции** — остальной код из инструкции.
3. Для **формы списка** в шаблоне заменить обозначения **объекта/таблицы формы** на фактическое имя таблицы (в примере — **`Элементы.Список`** / **`Список`** — по тексту занятия).
4. Подключить обработчик **при активизации строки** (имя таблицы согласовать с формой; можно создать обработчик через лупу — платформа подставит событие).
5. Опционально: реквизит формы **«Параметры подключаемых команд»** (**произвольный** тип) — служебная структура для подсистемы; если не добавить конструктором, подсистема могла бы добавить реквизит программно через **`ИзменитьРеквизиты`** — метод **тяжёлый**, число вызовов лучше **минимизировать** (см. синтакс-помощник).

---

### Блок 4. Смысл вставок кода

- **ПриСозданииНаСервере** — вызов программного интерфейса: создаются команды, подключённые к объекту (как созданные конструктором формы, так и из кода).
- Действие команды должно выполняться **клиентским** методом формы с параметром **`Команда`** — по нему подсистема **маршрутизирует** выполнение.
- Методы с префиксом **`Подключаемый`** задаются как действие команд, создаваемых в коде.
- Для контекстного перехода **клиент → сервер** используется цепочка с **оповещением** и **`ВыполнитьКомандуНаСервере`** (у последнего префикса «Подключаемый» уже нет) — вызов программного интерфейса на сервере.
- **При активизации строки** вызывается **`НачатьОбновлениеКоманд`**: через **обработчик ожидания** формы, чтобы при прокрутке стрелками не вызывать лишний пересчёт на каждую строку; по окончании навигации — **`ПодключаемыйОбновитьКоманды`**. Нужен **обработчик ожидания формы** (не глобальный), если требуется контекст формы.

---

### Блок 5. Форма документа

- Создать форму документа **«Приобретение товаров и услуг»**; вставить области из стандарта и код по инструкции для **формы объекта**.
- В параметрах передавать **`Объект`** как **`ДанныеФормыСтруктура`** (замены **`ОбъектФормы` → `Объект`** и т.п.).
- Дополнительно подключить события **при чтении на сервере**, **при открытии**, **после записи** — по инструкции; обработчики табличной части назвать по фактической таблице (**«Товары»**).
- Реквизит **параметры подключаемых команд** (произвольный тип).
- После изменения **ключевых реквизитов**, участвующих в условиях видимости, вызывать обновление команд:
  - с клиента — **`ПодключаемыеКомандыКлиент.НачатьОбновлениеКоманд`**;
  - если код уже на сервере — **`ПодключаемыеКомандыКлиентСервер.ОбновитьКоманды`** (имена модулей — по фактической поставке БСП).

---

### Блок 6. Первый результат: отчёты по движениям

- После обновления ИБ команды могут **не появиться**, пока к объекту **ничего не подключено**.
- Простой способ получить подменю **«Отчёты»** с отчётом по движениям: в метаданных документа **«Приобретение товаров и услуг»** в **движениях** указать хотя бы один **регистр накопления** (в примере — **«Демо остатки товаров в местах хранения»**).
- В пустом списке может отображаться **заглушка** подменю «Отчёты» — чтобы при изменении видимости подменю **не прыгало** по составу кнопок.

---

### Блок 7. Создание на основании (своя команда)

- Задача: по документу **«Приобретение товаров и услуг»** вводить **«Реализацию товаров и услуг»**.
- В документации БСП: раздел про **подключаемые команды** — **создание на основании**; рационально начать с примера с **функцией**, описывающей команду **реализации**.
- Логично разместить функцию в **модуле менеджера документа «Реализация товаров и услуг»**: проверка права **добавления**; добавление строки в таблицу **«Команды создания на основании»** с открытием формы; представление — из метаданных.
- Обычно не создают «на основании» от **непроведённого** документа — запрашивают **проведение** (**режим записи «Проводить»**), затем возвращают команду; иначе — **`Неопределено`**.
- В **модуле менеджера «Приобретение»** — метод, который вызывает **`ДобавитьКомандуСоздатьНаОсновании`** из менеджера **реализации**; прочие строки шаблона можно убрать.
- Если команда **одна**, подменю может **не создаться** — в демо добавляют вторую команду (например, «приобретение на основании приобретения») для показа **подменю**, копируя и подставляя тип документа.
- Зарегистрировать объект в **переопределяемом** модуле **«Создание на основании»** — метод **`ПриОпределенииОбъектовСКомандамиСозданияНаОсновании`**; код не писать в переопределяемом модуле «вручную», а вызвать общий модуль (в примере объединяют вызовы в **`ПодключаемыеКоманды_mp`** и добавляют **метаданные** документа «Приобретение…» в список объектов с такими командами).
- При выполнении открывается форма с параметрами заполнения; в **обработке заполнения** модуля объекта **реализации** данными заполнения будет **ссылка** на документ-основание.

---

### Блок 8. Условия видимости и обновление при смене склада

- Условия задаются в описании команды; для наглядности вызывают **`ДобавитьУсловиеВидимостиКоманды`** (общий модуль подключаемых команд): первая — **команда**, вторая — **реквизит** объекта и значение (в примере: **склад** равен складу **«Основной»**, поиск **`НайтиПоНаименованию`** — только для демо).
- Внутри проверки **`УсловияВыполняются`** передаётся **`Объект`** выбранных данных: для формы документа — обычно **`Объект`** формы; для динамического списка — **выбранные строки**; у колонок со **ссылкой** важен флаг **«Использовать всегда»**.
- Если обратиться к **несуществующему** реквизиту или неверному пути — условие может **не сработать** (в примере трактуется как истина — команда **не скрывается**): типичная **ловушка**.
- При **изменении склада** без вызова обновления команд видимость не обновится — в **`ПриИзменении`** склада вызвать **`ПодключаемыеКомандыКлиент.НачатьОбновлениеКоманд`** с передачей формы.

---

### Блок 9. Произвольная команда на форме списка («Демо счёт на оплату покупателям»)

- В **ПодключаемыеКомандыПереопределяемый** — метод **`ПриОпределенииКомандПодключенныхКОбъекту`** (при первом изменении — снять объекты с полной поддержки по правилам БСП); вызвать метод своего общего модуля подсистемы.
- Описание: **`ОписаниеКоманды = Команды.Добавить()`**; **`ТипПараметра`** — ссылка на нужный документ; **`Назначение`** — только для **списка** (строковая константа из документации).
- **Обработчик** — метод в клиентском/серверном общем модуле или менеджере; подсистема определяет контекст вызова.
- **Вид команды**: полноценно — через **`ПриОпределенииВидовПодключаемыхКоманд`** и таблицу **«Виды подключаемых команд»**; в демо используют технический вид **«Командная панель»** (в документации не найден — **не рекомендуется** для продуктива).
- Свойство **«Подменю»** — **служебное**, выводится из имени вида; прямое использование **не рекомендуется**; в примере привязка к группе **«Основные команды»** на форме списка.
- **Важно:** не опираться на **внутренние** объекты метаданных БСП и не писать **свои запросы** к служебным данным — при обновлении БСП доработки могут сломаться; использовать только **программный интерфейс** и **документацию** (ИТС).

**Параметры выполнения команды** (в т.ч. для обработчика):

- первый параметр — массив **ссылок** на объект;  
- второй — структура с полями вроде **Форма**, **Источник**, **ОписаниеКоманды**, **`ДополнительныеПараметры`** — туда можно передать произвольные данные для обработчика (пример: текст сообщения пользователю).

## Резюме

1. Подключаемые команды объединяют печать, отчёты, создание на основании и др.; видимость зависит от контекста и **множественного** выбора.  
2. На форме списка нужны **ссылка** и **«Использовать всегда»**; модуль формы — по **стандарту 400**.  
3. Вставки из инструкции: создание команд, **`Подключаемый`** обработчики, серверный вызов, **ожидание** для обновления команд.  
4. Отчёт по движениям — через **движения** документа по регистру.  
5. Создание на основании — менеджеры документов, регистрация в **`ПриОпределенииОбъектовСКомандамиСозданияНаОсновании`**, проведение основания, **обработка заполнения**.  
6. Условия видимости и обязательное **обновление команд** при смене реквизитов.  
7. Своя команда — **`ПриОпределенииКомандПодключенныхКОбъекту`**, тип параметра, обработчик, доп. параметры; избегать служебных приёмов вне ПИ.
